## 🔴 Critical Issues (Phải sửa ngay)

### C1. ai-handler.js — `classList` trên element null (GÂY LỖI TRÊN HÌNH ẢNH)
- **File:** `src/pages/create/ai-handler.js` — lines 144-145, 194-195, 308-309
- **Nguy hiểm:** Đây chính là lỗi **"Cannot read properties of null (reading 'classList')"** anh thấy trên màn hình. Khi `getElementById('step-brief')` hoặc `getElementById('step-loading')` trả về `null`, truy cập `.classList` sẽ crash ngay lập tức.
- **Khi nào xảy ra:** Nếu page chưa render xong hoặc DOM bị thay đổi bởi navigation trước khi AI hoàn thành.
- **Cách sửa:** Thêm optional chaining `?.classList` cho tất cả 6 dòng.

### C2. create.js — `classList` trên element null khi click Regenerate
- **File:** `src/pages/create.js` — lines 681-682
- **Nguy hiểm:** `getElementById('step-preview').classList.add('hidden')` — thiếu `?.`, crash nếu element không tồn tại.
- **Cách sửa:** Thêm optional chaining `?.classList`.

### C3. publish-handler.js — `publishBtn.disabled` và `resultsEl.classList` không có null check
- **File:** `src/pages/create/publish-handler.js` — lines 65-68
- **Nguy hiểm:** `publishBtn.disabled = true` và `resultsEl.classList.remove('hidden')` crash nếu element null. Cùng lỗi kiểu với C1.
- **Cách sửa:** Thêm null check hoặc early return nếu không tìm thấy element.

### C4. settings.js — Disconnect handlers thiếu null check
- **File:** `src/pages/settings.js` — lines 368-371 (Facebook) và 467-471 (WordPress)
- **Nguy hiểm:** Khi disconnect Facebook/WordPress, code truy cập `.value`, `.className`, `.innerHTML` trực tiếp trên `getElementById()` mà không check null. Nếu DOM bị lỗi sẽ crash.
- **Cách sửa:** Thêm optional chaining cho tất cả các dòng bị ảnh hưởng.

### C5. calendar.js — `modal-title` và `schedule-content-select` không có null check
- **File:** `src/pages/calendar.js` — lines 231, 283
- **Nguy hiểm:** `getElementById('modal-title').innerHTML = ...` crash nếu modal chưa render. `select.innerHTML = ...` cũng tương tự.
- **Cách sửa:** Thêm optional chaining hoặc null check.

## 🟡 Warnings (Nên sửa)

### W1. strategy.js — Event listener bị bind lại mỗi lần call `renderIdeas()`
- **File:** `src/pages/strategy.js` — line 293
- **Nguy hiểm:** Mỗi lần gọi `renderIdeas()`, event listener cho `btn-analyze-competitor` bị bind thêm 1 lần nữa. Nếu user generate chiến lược 3 lần → click "Phân tích đối thủ" → hàm `analyzeCompetitorGaps` bị gọi 3 lần, tiêu tốn gấp 3 API quota và hiển thị kết quả chồng chéo.
- **Cách sửa:** Di chuyển event listener cho competitor scanner ra hàm `attachStrategyEvents()` (bind 1 lần duy nhất).

### W2. strategy.js — `btn-use-strategy` click handler truy cập sai target
- **File:** `src/pages/strategy.js` — line 287
- **Nguy hiểm:** `e.target.dataset.json` — nếu user click vào icon bên trong button thì `e.target` là icon chứ không phải button → `dataset.json` là `undefined` → `JSON.parse(undefined)` crash. 
- **Cách sửa:** Dùng `e.currentTarget` hoặc `e.target.closest('.btn-use-strategy')`.

### W3. campaigns.js — Save handler thiếu null check khi lấy giá trị
- **File:** `src/pages/campaigns.js` — lines 186-189
- **Nguy hiểm:** `getElementById('campaign-name').value` — thiếu `?.`, crash nếu element không tồn tại (race condition khi modal chưa render).
- **Cách sửa:** Thêm optional chaining.

### W4. calendar.js — `schedule-time` thiếu null check
- **File:** `src/pages/calendar.js` — line 120, 306
- **Nguy hiểm:** `getElementById('schedule-time').value = ...` — thiếu optional chaining.
- **Cách sửa:** Thêm `?.value`.

### W5. create.js — `publishBtn.disabled = !anyOn` không check null
- **File:** `src/pages/create.js` — line 718
- **Nguy hiểm:** `publishBtn.disabled = !anyOn` — `publishBtn` có thể null, gây crash.
- **Cách sửa:** Thêm `if (publishBtn)` guard.

## 🟢 Suggestions (Tùy chọn)

### S1. Global unhandledrejection handler
- **File:** `src/main.js`
- **Lý do:** Hiện tại không có global error handler. Khi có Promise bị reject mà không catch, browser hiện toast vàng "Unhandled Promise Rejection" (như hình anh gửi). Thêm global handler sẽ bắt tất cả lỗi và hiển thị toast đẹp thay vì crash.
- **Gợi ý:** Thêm `window.addEventListener('unhandledrejection', ...)` trong `main.js`.

### S2. products-setup.js / customers-setup.js — querySelector thiếu null check
- **File:** `src/pages/products-setup.js` — lines 189-190, `src/pages/customers-setup.js` — lines 192-193
- **Lý do:** `card.querySelector('.item-name').value.trim()` — nếu card không có element `.item-name` sẽ crash. Một số dòng khác trong cùng file đã dùng optional chaining đúng cách, nhưng đoạn validation thì chưa.
- **Gợi ý:** Thêm optional chaining cho consistency.

### S3. brand.js — querySelector thiếu null check
- **File:** `src/pages/brand.js` — lines 354-355
- **Lý do:** `el.querySelector('.ctx-name').value.trim()` — tương tự S2, thiếu optional chaining.
- **Gợi ý:** Thêm `?.value?.trim() || ''`.
